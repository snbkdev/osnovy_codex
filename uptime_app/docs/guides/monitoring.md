# Автоматический мониторинг

Пока Go API запущен, четыре фоновых обработчика выбирают готовые к проверке мониторы из PostgreSQL. Первая GET-проверка выполняется после создания или изменения монитора. Следующая назначается через заданный интервал после завершения предыдущей; под нагрузкой возможна задержка. Страница запрашивает свежие результаты каждые 5 секунд.

Только HTTP 200 означает «Успешно». Другие HTTP-коды, включая редиректы, показываются как ошибка с кодом. Редиректы не выполняются. Тайм-аут проверки — 10 секунд; сетевые ошибки и заблокированные адреса имеют отдельные сообщения. Проверяются публичные HTTP/HTTPS-адреса: приватные, локальные и служебные диапазоны недоступны. Тело ответа не загружается целиком.

Последний результат сохраняется в monitors: status (`pending`, `success`, `error`), http_status (0 при отсутствии ответа), check_error, checked_at. История завершённых проверок сохраняется в `monitor_checks` вместе с URL на момент проверки. Рядом с сайтом ссылка «График» открывает `/monitors/<id>/history`: последние 24 часа, интервалы по 5 минут, зелёный — HTTP 200, красный — ошибка, серый — отсутствие проверок. В смешанном интервале высота цветных частей пропорциональна числу проверок; это не измерение длительности простоя. График обновляется каждые 10 секунд, выбор столбца показывает время и счётчики. После смены URL показываются проверки текущего адреса. История доступна только владельцу через `GET /api/v1/monitors/{id}/history`. Удаление монитора удаляет его историю. Редактирование сбрасывает результат и немедленно планирует новую проверку. Удаление прекращает планирование; уже начатый запрос может завершиться, но результат удалённого/изменённого монитора не сохраняется.

Блокировка строки и 30-секундная аренда защищают от параллельных проверок при нескольких процессах API. После сбоя проверка доступна повторно по истечении аренды. Выключенный API не проверяет сайты; после запуска просроченные проверки возобновляются.

## Обновление

Перед запуском новой версии примените миграцию `20261021000007_monitor_checks` и `20261021000008_monitor_history`:

```sh
make migrate-up
make migrate-status
```

Миграция сохраняет существующие мониторы и ставит их в очередь первой проверки. Откат удаляет результаты и расписание проверок, сохраняя URL, интервалы и владельцев. Откат выполняйте по [гайду миграций](migrations.md): команда откатывает всю последнюю группу, которая может включать другие миграции.

После миграции перезапустите API и frontend штатным способом. В браузере проверьте создание монитора с публичным URL, HTTP 200, ответ с другим кодом, обновление статуса без перезагрузки страницы и изменение URL/интервала.

Миграция истории переносит один последний известный результат каждого монитора, если он есть. Более ранние проверки восстановить невозможно. Откат `20261021000008` удаляет таблицу истории и её данные, сохраняя мониторы и последний статус. Существующая версия API после добавления таблицы продолжает работать; для накопления новых записей перезапустите обновлённый API.
