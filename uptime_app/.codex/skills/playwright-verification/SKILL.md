# Проверка реализации через Playwright MCP

Все действия с браузером (навигация, взаимодействие, скриншоты, консоль и сетевые запросы) выполняй через **Playwright MCP**. CLI-тесты дополняют эту проверку, но не заменяют ее.

## Подготовка

1. Прочитай корневой `AGENTS.md` и инструкции затронутого приложения. Команды выполняй из `uptime_app/`.
2. По запросу и фактическим изменениям определи ожидаемый результат, страницы и сценарии: основной путь и относящиеся к задаче ошибки и граничные состояния.
3. Найди инструменты Playwright MCP в текущей сессии по имени и описанию; не предполагай конкретный префикс.
4. Проверь нужные локальные сервисы. При необходимости запусти их штатными командами (`make dev` или команда отдельного приложения), сохраняя существующие настройки. Используй фактический адрес приложения. Для API-интеграций нужны frontend и backend; для почтовых сценариев также нужен тестовый почтовый сервис.

Если MCP или нужный сервис недоступен, сообщи о блокере и непроверенных сценариях. Не подменяй MCP другим браузерным инструментом и не объявляй проверку успешной.

Для документации и изменений без наблюдаемого эффекта в браузере объясни неприменимость и выполни подходящие небраузерные проверки. Отсутствие MCP или сервиса — блокер, а не неприменимость.

## Функционал

- Открой затронутые страницы через MCP и выполни сценарий реальными переходами, вводом, нажатиями и отправкой форм. Подтверди ожидаемый результат значимых действий.
- Проверь относящиеся к задаче состояния загрузки, пустых данных, валидации, ошибок и успеха. Для сохраняемых изменений проверь результат после перезагрузки или повторного открытия страницы.
- Используй тестовые данные и учетные записи. Не выполняй необратимые действия с реальными данными ради проверки.
- Для API-интеграций проверь запросы через `/api/*`, ответы и отображение результата. Если затронута связь frontend с API, проверь кнопку статуса API и `/api/v1/health`.
- Просмотри консоль и неуспешные сетевые запросы через MCP. Установи связь ошибок с изменением; отделяй существовавшие проблемы от новых регрессий.

## Верстка

- Посмотри отрисованные страницы на скриншотах Playwright MCP. DOM или accessibility snapshot используй для структуры и элементов управления; одного такого снимка недостаточно для оценки верстки.
- Проверь настольный и мобильный размеры окна; добавь промежуточный размер, если затронуты адаптивные переходы. Запиши фактические размеры окна.
- Оцени выравнивание, отступы, читаемость, переносы, изображения, обрезание содержимого, перекрытия и непредусмотренный горизонтальный скролл. Для затронутых диалогов, меню и форм проверь открытое и заполненное состояния.
- Проверь измененные элементы с клавиатуры, видимость фокуса и понятные подписи. Сверяй внешний вид с предоставленным макетом и требованиями, если они есть.

## Исправления и отчет

Исправляй дефекты в пределах задачи и повторяй затронутые функциональные и визуальные проверки после исправлений. Выполни также проверки кода из `AGENTS.md`: браузерная проверка их не заменяет.

Перед завершением кратко сообщи:

- проверенные страницы, сценарии и результат;
- размеры окна и пути к сохраненным скриншотам, если они сохранены;
- связанные ошибки консоли и сетевых запросов;
- исправленные и перепроверенные дефекты, заблокированные или неприменимые проверки с причиной.

Не заявляй об успешной проверке без фактического выполнения через Playwright MCP. При блокере отделяй выполненную реализацию от непроверенного поведения.
