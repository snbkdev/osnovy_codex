# Документирование роутов через Swaggo

Поддерживай соответствие зарегистрированных API-операций, Swaggo-аннотаций и сгенерированной спецификации. При отдельном запросе на документирование охвати все существующие API-роуты; при разработке конкретного роута обнови его документацию и затронутые общие схемы.

## Определение контракта

Прочитай инструкции репозитория и найди регистрацию маршрутов, обработчики, middleware, DTO, глобальные Swaggo-аннотации и команду генерации. Учитывай вложенные роутеры, ручную диспетчеризацию по пути/методу и условную регистрацию: поиск только HandleFunc не даёт полного списка операций.

Для каждой пары метод/путь установи параметры, обязательность, тело, типы содержимого, успешные ответы, ошибки и требования авторизации по реализации и тестам. Учитывай ответы middleware, в том числе ограничения частоты и размера запроса. Не добавляй гипотетические статусы или авторизацию по аналогии с соседними роутами. Swagger UI и выдачу самой спецификации не включай в бизнес-операции API.

## Аннотации

Добавляй или исправляй комментарии непосредственно перед соответствующим обработчиком; сохраняй существующие соглашения о языке, тегах и именах схем.

- Указывай `@Summary`, `@Tags`, применимые `@Accept` и `@Produce`, `@Param`, `@Success`, `@Failure` и `@Router`.
- В `@Router` используй путь относительно глобального `@BasePath` и метод в нижнем регистре. Не дублируй префикс; учитывай path-параметры вида `{id}`.
- Описывай path/query/header/formData/body-параметры с фактическими типами и обязательностью. Для загрузки файлов отражай multipart и поле файла.
- Ссылайся на реальные сериализуемые DTO и точную форму ответа: объект, массив, оболочка, файл или ответ без тела. Не используй модели хранения вместо фактического ответа. Для общих входных структур учитывай, какие поля конкретный обработчик действительно читает и требует.
- Добавляй `@Security` в соответствии с реальным механизмом доступа и существующим определением security scheme. Для cookie, refresh и logout учитывай фактические cookies и заголовки; не подменяй их Bearer-аутентификацией.
- При изменении общих DTO проверяй все использующие их операции. При удалении роута удаляй устаревшую операцию.

Сохраняй поведение API. Если точную схему нельзя выразить существующими типами, добавь минимальный тип для документации без изменения выполнения и проверь результат генератора.

## Генерация и проверка

Используй команду и версию генератора из проекта. Не редактируй генерируемые файлы вручную и не заменяй Swaggo другим инструментом. Сохраняй текущую версию формата спецификации: Swagger 2.0 не нужно конвертировать в OpenAPI 3 без отдельного запроса.

Для uptime_app, из корня приложения:

- Источник маршрутов и обработчиков: `backend/internal/httpapi/`, глобальные аннотации: `backend/cmd/api/main.go`; `@BasePath /api/v1`, схема доступа `BearerAuth`.
- После синхронизации аннотаций обязательно запусти `bash .codex/skills/swaggo-routes/scripts/sync-docs.sh`. Скрипт последовательно выполняет `make swagger`, затем генерацию ReDoc через `make redoc`, затем `go test ./internal/httpapi` из `backend/`; при ошибке останавливается. Его можно запускать из любой директории, указав путь к скрипту. Результаты: `backend/docs/docs.go`, `backend/docs/swagger.json`, `backend/docs/swagger.yaml`, `backend/docs/redoc.html`.
- При добавлении или удалении операций синхронизируй ожидаемые операции в `backend/internal/httpapi/router_test.go` с регистрацией маршрутов.
- Синхронизируй список ожидаемых операций до запуска скрипта. Дополнительные проверки выбирай по изменённому коду и инструкциям репозитория.

В других проектах используй их пути и команды вместо этих локальных соглашений.

Сверь сгенерированные пары метод/путь с фактическими API-роутами, проверь отсутствие пропущенных, лишних или дублирующихся операций и проверь изменённые схемы и security. Успешная генерация сама по себе не доказывает полноту документации. Если генерация или проверка не завершилась, сообщи причину и не утверждай, что артефакты актуальны.

В результате кратко укажи документированные операции, обновлённые артефакты и выполненные проверки.
